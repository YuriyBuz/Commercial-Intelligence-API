# FOODLINE · Лінії — облік роботи та обслуговування виробничих ліній

Застосунок для планшетів біля ліній і для керівництва: щоденні чек-листи, стан кожної лінії,
ремонти, налаштування, ТО і ППР, лічильники, нагадування про обслуговування. Усі дані й
налаштування обладнання зберігаються у вашій Google-таблиці.

**Адреса застосунку:** <https://yuriybuz.github.io/Commercial-Intelligence-API/lines/>
(ту саму адресу відкривають і планшети, і комп'ютер керівника).

## 1. Що це і що вміє

### Щоденна робота операторів

- Біля лінії стоїть планшет. Оператор обирає себе у списку (за потреби вводить свій PIN).
- Перед запуском він проходить **чек-лист запуску**: відмічає вузли й деталі
  («Норма» / «Зауваження» / «Н/З»), вносить параметри (числа з нормою), обирає варіанти,
  пише коментарі. Є також чек-листи **переналаштування** і **завершення** роботи.
- Кожна зміна стану лінії записується з часом і прізвищем: запуск, простій із причиною,
  налаштування й переналаштування, миття, ремонт, ТО / ППР, завершення роботи.

### Облік обладнання й виконаних робіт

- Керівник додає **лінії** та їхні **агрегати**, **пункти чек-листів і параметри контролю**,
  **лічильники** і **регламент ТО і ППР** — у застосунку («Керівництво → Обладнання») або
  прямо в Google-таблиці.
- Зберігається повна історія: зміни стану, чек-листи з усіма відповідями, роботи
  (налаштування, переналаштування, ремонт, ТО, ППР, заміна деталі, змащування, миття,
  калібрування, огляд), показники лічильників.

### Планування ТО / ППР і нагадування

- Для кожної роботи регламенту задаються умови: **кожні N днів**, **кожні N мотогодин**
  і/або **кожні N одиниць лічильника** — строк настає за тією умовою, що настане раніше.
- З накопичених даних система будує **план ППР** на рік уперед (аркуш «План ППР»).
- Нагадування приходять **на e-mail** (щоденний звіт і миттєві листи) та видно
  **на планшеті** біля лінії.

### Ключові поняття

**Стани лінії** (кольорова мітка на плитці й екрані лінії):

| Стан | Що означає |
|---|---|
| Не працює | лінія вимкнена, зміна завершена |
| Працює | випуск продукції — **лише в цьому стані рахуються мотогодини** |
| Простій | тимчасова зупинка з причиною (перерва, немає тари, мікрозупинка…) |
| Налаштування | налаштування або переналаштування на інший продукт / формат |
| Ремонт | поломка, аварійна зупинка (керівництву йде лист) |
| ТО / ППР | планове обслуговування |
| Миття | санобробка |

**Мотогодини** ніхто не вводить вручну: система сама рахує час, який лінія провела в стані
«Працює». Напрацювання агрегату = «Мотогодини до початку обліку» (з паспорта чи лічильника,
задаєте один раз) + мотогодини лінії відтоді, як агрегат додано.

**Лічильники** — будь-які інші показники (цикли, вироблені одиниці тощо). Два типи
(однакові назви в застосунку й у стовпці «Тип обліку» таблиці):
«Накопичувальний показник» (число з табло, лише зростає) і «Приріст за зміну» (скільки
додалося). Оператор вносить їх кнопкою «Лічильники» або в чек-листі завершення.
Накопичувальний показник, менший за попередній, застосунок і сервер **не приймуть як звичайний**:
це або помилка вводу (виправте число), або лічильник замінили / скинули — тоді оператор
натискає **«Лічильник скинуто / замінено»**, і напрацювання для строків ТО далі рахується
з нового числа, продовжуючи вже набране (строк ТО не «обнуляється» і не стає від'ємним).

**Регламент ТО і ППР** — перелік робіт з інтервалами. Для кожної роботи система показує
статус:

| Статус | Коли |
|---|---|
| У нормі | до строку ще далеко |
| Скоро | використано ≥ 90 % інтервалу **або** до строку ≤ 7 днів (пороги можна змінити загалом чи для окремої роботи) |
| Потрібно виконати | інтервал вичерпано (прострочено) |
| Без інтервалу | інтервал не задано |

Коли роботу позначено виконаною («Позначити виконаним» або запис роботи за регламентом),
відлік починається заново.

Для календарного інтервалу «залишилось N дн.» / «прострочено на N дн.» — це різниця
**календарних днів** заводу (строк 01.10, сьогодні 30.09 → «залишилось 1 дн.»; строк
настав сьогодні — «строк настав сьогодні»). Коли перевищено інтервал за мотогодинами чи
лічильником, «строк» у листах і плані — момент, коли поріг справді перейшли (за журналом
стану / між двома показниками), а не прогноз «назад» за середнім.

**Контроль чек-листів.** Результат чек-листа: «Норма», «Із зауваженнями» або «Не пройдено».
«Не пройдено» — зауваження в **критичному** пункті або пропущений обов'язковий пункт.
«Н/З» у критичному пункті вважається зауваженням; в обов'язковому «Н/З» приймається лише
з поясненням у примітці, інакше це теж зауваження. Чек-лист запуску чинний 12 годин
(`checklist_valid_hours`), але лише доки лінію, що вже працювала, не переведуть у «Не працює»:
нова зміна — новий чек-лист. Миття, налаштування чи ТО **до запуску** з переходом у
«Не працює» чек-лист не «витрачають» (це підготовка): після них можна одразу «Запустити»,
і оператор лишається вибраним на планшеті.
Порушення позначаються в журналі:
«Запуск без чек-листа», «Завершення без чек-листа», «Запуск попри зауваження».
Позначка «без чек-листа» на плитці й екрані лінії з'являється, лише якщо **запуск цієї роботи**
був без чинного чек-листа і відтоді чек-лист запуску так і не пройшли (довга зміна після
чек-листа — не порушення, для неї окреме попередження «понад 16 год без завершення»).
Керівник бачить матрицю «лінія × день» і відсоток запусків із чек-листом. День, на який
припав запуск без чек-листа, завершення без чек-листа **або початок зміни, що тривала довше
за `long_run_hours` (16 год) без завершення**, позначається «Без чек-листа» (✕).

## 2. Швидко спробувати

Нічого встановлювати не потрібно.

1. Відкрийте <https://yuriybuz.github.io/Commercial-Intelligence-API/lines/> (Chrome, Edge або Safari).
2. Оберіть **«Демо на цьому пристрої»** → **«Далі»**.
3. Зачекайте повідомлення «Демо-дані готові» → **«Далі»**.
4. Введіть «Назва пристрою» (будь-яку) → **«Почати роботу»**.

У демо — соусний завод: 3 лінії, агрегати, чек-листи, регламент ТО й історія за 35 днів.

- Розділ керівника: меню **☰ → «Керівництво»**, **PIN 1234**.
- Оператор «Олена Коваленко» має PIN **1111**, інші демо-працівники — без PIN.

> **Дані демо-режиму зберігаються лише в цьому браузері на цьому пристрої.** Їх не бачать
> інші планшети, вони не потрапляють у Google-таблицю й зникнуть після очищення даних
> браузера. Листи в демо не надсилаються (у «Журналі сповіщень» вони позначені
> «демо: не надсилалось»). Почати заново: **☰ → «Пристрій» → «Скинути демо-дані»**.
> Перейти на справжню таблицю: **☰ → «Пристрій» → «Підключити таблицю» → «Увійти як
> керівник»** (у демо PIN **1234**) → далі майстер, як у кроці [3.9](#39-підключення-планшетів).

## 3. Розгортання крок за кроком

**Що потрібно:** обліковий запис Google (він стане «власником»: листи йтимуть з його пошти,
а таблиця й скрипт лежатимуть на його Диску), планшети з Chrome і Wi-Fi з доступом
до інтернету. Розгортання займає орієнтовно пів години.

### 3.1. Google-таблиця

Створіть нову порожню Google-таблицю, наприклад «Облік ліній». Аркуші створювати не потрібно —
це зробить скрипт.

### 3.2. Apps Script: три файли

1. У таблиці: **Розширення → Apps Script**. Відкриється редактор із файлом `Code.gs`.
2. Перейменуйте `Code.gs` на **`Core.gs`** (⋮ біля назви → «Перейменувати») і замініть весь
   його вміст на **повний вміст файлу** [`lines/assets/core.js`](https://github.com/YuriyBuz/Commercial-Intelligence-API/blob/main/lines/assets/core.js).
   На GitHub зручно скористатися кнопкою «Copy raw file» (значок копіювання над текстом файлу).
3. Додайте другий файл (кнопка **«+»** біля «Файли» → «Скрипт»), назвіть його **`Server`**
   (редактор сам додасть `.gs`) і вставте вміст
   [`lines/apps-script/Server.gs`](https://github.com/YuriyBuz/Commercial-Intelligence-API/blob/main/lines/apps-script/Server.gs).
4. **⚙ Налаштування проєкту** → увімкніть «Показувати файл маніфесту appsscript.json у редакторі».
   Поверніться до редактора, відкрийте `appsscript.json` і замініть його вміст на
   [`lines/apps-script/appsscript.json`](https://github.com/YuriyBuz/Commercial-Intelligence-API/blob/main/lines/apps-script/appsscript.json).
   Якщо редактор не приймає пояс `Europe/Kyiv`, напишіть `Europe/Kiev`: це той самий пояс
   (стара назва), і «Початкове налаштування» вважає їх однаковими.
5. Збережіть проєкт (значок дискети або Ctrl+S).

### 3.3. Початкове налаштування і дозволи

1. Ліворуч у списку файлів відкрийте **`Server.gs`**. У списку функцій на панелі над кодом
   оберіть **`setup`** → **«Виконати»**. (Список показує функції лише відкритого файлу:
   у `Core.gs` і `appsscript.json` функції `setup` немає.)
   Або оновіть сторінку таблиці — з'явиться меню **«Облік ліній»** — і виберіть
   **«Облік ліній → Початкове налаштування»**.
2. Google попросить дозволи: **«Перевірити дозволи»** (з меню таблиці Google спершу покаже
   «Потрібна авторизація» → «Продовжити») → оберіть свій обліковий запис.
3. З'явиться попередження **«Google не перевірив цей застосунок»** (Google hasn't verified
   this app). Для власного скрипту це нормально: **«Додатково»** (Advanced) →
   **«Перейти до <назва проєкту> (небезпечно)»** → **«Дозволити»**.

   Google покаже дозволи в загальному вигляді: «переглядати, редагувати, створювати й
   видаляти всі ваші таблиці» (без цього не можна створити таблицю-архів; фактично скрипт
   працює лише з цією таблицею й архівом), запуск за розкладом, коли вас немає поруч
   (тригери), надсилання листів від вашого імені, показ вікон у таблиці. Інших даних скрипт
   не читає.
4. Скрипт створить 14 аркушів, заповнить «Налаштування», згенерує **токен доступу** і
   **PIN керівника**, а також створить два тригери: щоденний звіт (типово в проміжку
   7:00–8:00) і щогодинну перевірку строків ТО. Якщо запускали з меню таблиці, з'явиться
   вікно з підсумком і наступними кроками. Якщо запускали з редактора, у редакторі вікна не
   буде: підсумок дивіться внизу в «Журналі виконання». Якщо таблиця відкрита в іншій
   вкладці, вікно може з'явитися там; натисніть OK. Якщо після надання дозволів нічого не
   з'явилося, виберіть пункт меню ще раз: повторний запуск безпечний.

### 3.4. Розгортання веб-застосунку

1. У редакторі Apps Script: **Розгорнути → Нове розгортання**.
2. Тип (⚙ біля «Виберіть тип»): **«Веб-застосунок»**.
3. **Виконувати від імені: «Я»** (Me). **Хто має доступ: «Будь-хто»** (Anyone).
4. **«Розгорнути»** → скопіюйте **URL веб-застосунку**. Він закінчується на **`/exec`**.

> Адреса, що закінчується на `/dev`, — тестова: вона працює лише для редакторів проєкту,
> а на планшетах — ні. Застосунок таку адресу не прийме.
>
> «Будь-хто» означає, що планшетам не потрібен вхід у Google. Без токена сервер нічого не
> віддає й не приймає. Якщо у вашому Google Workspace варіанта «Будь-хто» немає, його має
> дозволити адміністратор домену.

### 3.5. Адреса /exec у меню таблиці

Поверніться до таблиці (за потреби оновіть сторінку) → **«Облік ліній → Вказати адресу
веб-застосунку (/exec)»** → вставте скопійовану адресу → OK.

### 3.6. Токен і PIN

**«Облік ліній → Показати токен і PIN»** покаже:

- **адресу API** (…/exec) і **токен доступу** (24 символи) — їх вводять на кожному планшеті;
- **PIN керівника** (6 цифр) — для розділу «Керівництво». Якщо міняєте його у властивостях
  скрипту, лише 4–8 цифр: інший PIN на планшеті не ввести (setup і «Показати токен і PIN»
  про це попередять).

Не передавайте токен і PIN стороннім. Як їх змінити, описано в розділі [10](#10-обмеження-й-поради).

### 3.7. Email керівників

Без жодної адреси листи-нагадування **не надсилаються**. Задайте адреси будь-яким способом:

- у таблиці: аркуш **«Налаштування»**, рядок `manager_emails`, стовпець «Значення»
  (кілька — через кому);
- або пізніше в застосунку (після кроку 3.9): **Керівництво → Налаштування → «Email керівництва»**;
- та/або вкажіть «Email» працівникам на аркуші / в розділі **«Персонал»**: кому які листи
  приходять, описано в розділі [7](#7-нагадування).

Також задайте **«Адреса застосунку»** (рядок `app_url` на тому ж аркуші) =
`https://yuriybuz.github.io/Commercial-Intelligence-API/lines/`, щоб у листах була кнопка
«Відкрити „Облік ліній“».

Перевірка: **«Облік ліній → Надіслати звіт зараз»**. Звіт прийде, навіть якщо нічого
термінового немає.

### 3.8. Лінії, обладнання, персонал

Відкрийте застосунок на комп'ютері, підключіть його як планшет (крок 3.9, без закріпленої
лінії) і в **Керівництво → Обладнання** додайте лінії, агрегати, пункти чек-листів,
лічильники й регламент ТО. У **«Персонал»** додайте людей. Усе це можна вносити й прямо
в таблиці (розділ [6](#6-google-таблиця)).

> Щоб спершу потренуватися, **не заповнюйте демо-даними робочу таблицю**: демо-лінії мають
> прострочене ТО, і керівники з `manager_emails` одразу отримають про них листи, а вичистити
> демо-записи з журналів неможливо. Створіть окрему нову таблицю, повторіть для неї кроки
> 3.1–3.4 (у неї буде своя адреса /exec і свій токен), **не вказуйте в ній email керівників**
> і лише тоді виберіть «Облік ліній → Заповнити демо-даними» (працює лише в порожній
> таблиці). Копія робочої таблиці («Файл → Створити копію») для цього не годиться: вона
> копіює й `manager_emails`. Або просто спробуйте демо-режим на планшеті (розділ [2](#2-швидко-спробувати)).

### 3.9. Підключення планшетів

На кожному планшеті відкрийте адресу застосунку. Запуститься майстер налаштування з трьох кроків:

1. **«Режим»** → **«Google-таблиця підприємства»** → «Далі».
2. **«Підключення»** → вставте «Адреса веб-застосунку (/exec)» і «Токен доступу» →
   **«Перевірити зв'язок»**. Має з'явитися «Зв'язок є» з назвою підприємства й кількістю ліній → «Далі».
3. **«Пристрій»**:
   - «Назва пристрою», наприклад «Планшет лінії 1». Вона записується в кожен запис;
   - «Закріпити за лінією»: закріплений планшет одразу відкриває екран своєї лінії
     (для комп'ютера керівника — «Не закріплювати — усі лінії»);
   - «Тема оформлення»: «Темна» або «Світла (яскравий цех)».

   Потім натисніть **«Почати роботу»**.

Змінити пізніше можна в **☰ → «Пристрій»**. Назву, закріплення й тему там змінюють вільно.
Для «Змінити підключення» потрібен PIN керівника. Якщо немає зв'язку або токен уже невірний,
є кнопка «Змінити без входу».

### 3.10. Встановлення як застосунок і режим кіоску

**Встановлення (рекомендовано).** Chrome на Android: меню ⋮ → «Встановити застосунок» /
«Додати на головний екран». Якщо браузер пропонує встановлення, у меню застосунку ☰ також
є пункт «Встановити застосунок». На iPad: Safari → «Поділитися» → «На початковий екран».
Після першого відкриття з інтернетом застосунок запускається й без мережі (розділ [9](#9-офлайн-робота-планшета)).

**Щоб оператор не виходив із застосунку (Android):**

- **Закріплення екрана.** Увімкніть у налаштуваннях Android пункт «Закріплення
  програми / екрана». Зазвичай він у розділі «Безпека»; на Samsung — «Біометрія та безпека →
  Інші налаштування безпеки». Назва залежить від виробника, тож найпростіше знайти його
  пошуком у налаштуваннях за словом «закріп». Увімкніть також запит PIN перед відкріпленням.
  Потім відкрийте застосунок → список недавніх програм → значок застосунку над його вікном →
  «Закріпити».
- **Екран не гасне:** задайте максимальний час вимкнення екрана або ввімкніть
  «Не вимикати екран під час заряджання» (у параметрах розробника).
- *(Необов'язково)* **Fully Kiosk Browser** — окремий браузер-кіоск для Android: стартова
  сторінка = адреса застосунку, блокування виходу, автозапуск. Частина функцій (зокрема
  кіоск-режим) доступна лише з платною ліцензією. Після налаштування перевірте, що застосунок
  відкривається без мережі.
- На iPad аналог закріплення — «Гід-доступ» (Параметри → Універсальний доступ).

### 3.11. Оновлення коду без зміни адреси

1. Замініть вміст `Core.gs` і `Server.gs` новими версіями (а також `appsscript.json`, якщо він змінився).
   Сторінка застосунку оновлюється з GitHub сама, тому щоразу, коли на GitHub виходить нова
   версія, того ж дня оновіть і `Core.gs` / `Server.gs` за цими кроками. Перевірка:
   ☰ → «Пристрій» → «Про застосунок»: номер «ядро v…» має збігатися з «Сервер v…»
   (якщо ні, там же з'явиться червона підказка).
2. **«Облік ліній → Початкове налаштування»**. Дані це не змінює: скрипт лише додасть нові
   аркуші, стовпці й налаштування та попросить нові дозволи, якщо вони потрібні.
3. **Розгорнути → Керування розгортаннями → ✎ (Редагувати) → Версія: «Нова версія» → «Розгорнути».**
   Адреса `/exec` лишається тією самою, тож планшети перенастроювати не потрібно.

> Не створюйте «Нове розгортання» для оновлення: воно дасть **нову** адресу, і всі планшети
> доведеться перепідключати.

Сама вебсторінка оновлюється з GitHub. На планшетах з'явиться «Доступна нова версія
застосунку» → «Оновити». Можна й вручну: **☰ → «Оновити»** або «Пристрій → Оновити застосунок».

## 4. Щоденна робота оператора

Екран лінії відкривається дотиком до плитки лінії (закріплений планшет відкриває його одразу).
Під час першої дії застосунок спитає **«Хто працює на лінії?»**: торкніться свого імені
(і введіть PIN, якщо він заданий) або виберіть «Інша людина». Оператор лишається вибраним
до 14 годин. Змінити його можна кнопкою з іменем у верхній панелі
(у ній же є «Завершити зміну»).

**Початок зміни**

1. **«Підготовка і запуск»** → відкриється чек-лист запуску.
2. Вкажіть «Продукт / формат». Пройдіть пункти: «Норма» / «Зауваження» / «Н/З», числа,
   варіанти. До зауваження додайте примітку.
3. **«Перевірити й завершити»** → підсумок → **«Запустити лінію»** (або «Зберегти без запуску»).
   Якщо в критичному пункті є зауваження, кнопки будуть такі: «Не запускати — викликати ремонт» або
   «Запустити під мою відповідальність». Для другого варіанта коментар обов'язковий.

Якщо чек-лист запуску ще чинний (наприклад, лінію ненадовго зупиняли), замість цього буде
кнопка «Запустити».

**Під час роботи**

- **«Простій»** → причина (для «Інше» — коротка примітка) → «Зафіксувати простій».
  Потім **«Відновити роботу»**.
- **«Переналаштування»** → новий продукт / формат → «Почати переналаштування».
  Після роботи натисніть **«Налаштування завершено»** → «Запустити лінію»: відкриється чек-лист,
  у ньому можна записати «Параметри налаштування» і «Хто налаштовував».
- **«Ремонт»** → «Що сталося?», агрегат → «Почати ремонт» (керівництво отримає лист).
  Після ремонту: **«Ремонт завершено»** → що зроблено, замінені деталі → «Зберегти і далі» →
  «Запустити лінію» або «Зупинити лінію».
- **«Лічильники»** — внести показники. **«Записати роботу»** — будь-яка робота
  (заміна деталі, змащування тощо). **«Історія лінії»** — останні 14 днів.

**Коли лінія не працює** доступні також **«Налаштування»**, **«Миття»** («Почати миття» →
«Миття завершено») і **«ТО / ППР»** (вибрати заплановані роботи → «Почати ТО» →
«ТО завершено» → записати виконане). Миття чи налаштування **перед запуском** (після чек-листа
запуску, коли лінія ще не працювала) чек-лист не «витрачають»: після «Миття завершено» лінія
в «Не працює», оператор лишається вибраним, і можна одразу «Запустити».

**Лічильники.** Якщо накопичувальний показник менший за попередній, застосунок спитає, що
сталося: **«Виправити число»** (помилка вводу) або **«Лічильник скинуто / замінено»** —
тоді показник запишеться як новий відлік, а напрацювання для строків ТО продовжиться з нього.

**ТО на екрані лінії.** Панель «ТО і ППР» показує прострочені й близькі роботи. Дотик до
роботи відкриває подробиці та інструкцію, там є кнопка **«Позначити виконаним»**.

**Кінець зміни**

1. **«Завершити роботу»** → чек-лист завершення (у ньому ж показники лічильників,
   для яких увімкнено «Питати при завершенні роботи»).
2. **«Перевірити й завершити»** → **«Завершити роботу»**. Лінія перейде в «Не працює»,
   а оператора буде знято з планшета.

## 5. Кабінет керівника

**☰ → «Керівництво»** → PIN керівника (вхід діє до закриття вкладки браузера). Дії керівника
виконуються лише за наявності зв'язку з сервером.

| Розділ | На що відповідає |
|---|---|
| **Огляд** | Що зараз на лініях: «Працюють зараз», «Прострочено ТО», «Скоро ТО», «Чек-листи запуску · 7 дн.» (% запусків із чек-листом), «Простої · 7 дн.», «Ремонти · 7 дн.», таблиця «Стан ліній». За вибраний період (7 / 14 / 30 / 62 дні або свій): щоденні перевірки, роботи, ремонти й простої, години за станами, причини простоїв, агрегати, зауваження. Кнопка «CSV» вивантажує дані для Excel |
| **ТО і ППР** | Що й коли обслуговувати: «Строки ТО» (фільтри за статусом, лінією, агрегатом; «Позначити виконаним»), «План робіт», «Річний графік». Є «CSV» і «Друк» |
| **Журнал** | Що відбувалося: усі записи (стан ліній, чек-листи, роботи, лічильники) з фільтрами й пошуком. Помилковий запис можна **«Анулювати»** із зазначенням причини: він лишається в таблиці з позначкою |
| **Чек-листи** | Чи виконуються щоденні перевірки: % запусків із чек-листом по лініях, матриця «лінія × день» (✓ виконано, ! із зауваженнями, ✕ без чек-листа, → робота без запуску), список чек-листів із відповідями |
| **Обладнання** | Лінії та для кожної з них вкладки «Агрегати», «Чек-лист і параметри» (є «Скопіювати з іншої лінії»), «Лічильники», «Регламент ТО і ППР». Записи не видаляються, а **вимикаються**: історія зберігається |
| **Персонал** | Хто є в списку на планшетах: посада, лінії, email, PIN |
| **Налаштування** | Параметри підприємства, звітів, ТО, чек-листів і планшетів; попередній перегляд щоденного звіту; «Журнал сповіщень» (кому й коли пішли листи, помилки); «Перерахувати» |

### Правила ручного редагування

- **Сірі стовпці** (з приміткою «Службовий стовпець») заповнює система: поточний стан лінії,
  мотогодини, останнє виконання робіт регламенту, поточні значення лічильників. Не змінюйте їх.
- **Журнали не сортуйте й не видаляйте в них рядки**: нові записи додаються вниз. Для
  перегляду користуйтеся фільтром. Помилковий запис анулюйте в застосунку
  (Керівництво → Журнал). Якщо журнал усе ж правили вручну, запустіть «Облік ліній →
  Перерахувати мотогодини».
- **Не перейменовуйте заголовки.** Стовпці система знаходить за назвою, тож їхній порядок
  можна міняти, а власні стовпці додавати праворуч.
- **Не видаляйте рядки довідників**, на які вже є записи: зніміть прапорець
  «Активна» / «Активний».
- **ID** — унікальний і незмінний код рядка. Використовуйте латинські літери, цифри, `-`, `_`,
  наприклад `L4`, `U41`, `I120`, `R12`. Застосунок генерує ID сам. Рядок без ID або з
  повтореним ID пропускається, і на «Огляді» керівника з'являється попередження. Рядок, доданий
  у таблиці з ID кирилицею чи з пробілом (напр. «Лінія 4»), працює й редагується в застосунку,
  але нові ID застосунок приймає лише латиницею.
- Прапорці: «так» / «ні» (або TRUE / FALSE). Порожній «Активний» / «Обовʼязковий» означає «так».
- «Коли» — через кому: `Запуск`, `Переналаштування`, `Завершення`.
  **Порожнє (або невідоме) «Коли» — пункт не з'явиться в жодному чек-листі**; на «Огляді»
  керівника такий активний пункт буде в списку «потребують виправлення».
- Зміни в таблиці з'являються на планшетах протягом ~1,5 хв (`refresh_sec`) або одразу після
  **☰ → «Оновити»**.
- **Часовий пояс** змінюйте лише в застосунку (Керівництво → Налаштування → «Часовий пояс»):
  застосунок сам переведе таблицю, зберігши час записів. Не змінюйте його у «Файл →
  Налаштування таблиці»: Google зсуне час усіх уже записаних дат.
- Некоректне значення параметра на аркуші «Налаштування» мовчки замінюється типовим
  (число поза межами обрізається до допустимого). Надійніше змінювати параметри в застосунку:
  там значення перевіряються.

### Як додати пункт чек-листа прямо в таблиці

Новий рядок на аркуші «Чек-листи і параметри»:

| ID | ID лінії | ID агрегату | Коли | Розділ | Пункт / параметр | Тип | Од. виміру | Мін | Макс | Норма | Варіанти | Обовʼязковий | Критичний |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| I120 | L1 | U12 | Запуск, Переналаштування | Параметри | Момент закручування кришки | Число | Н·м | 1,8 | 2,4 | 2,0 | | так | ні |
| I121 | L1 | | Запуск | Налаштування | Маркування дати | Вибір | | | | | Чітке; !Нечітке; !Відсутнє | так | ні |

- «ID лінії» / «ID агрегату» беруться зі стовпця ID аркушів «Лінії» / «Агрегати». Якщо
  «ID агрегату» порожній, пункт стосується лінії загалом.
- «Тип»: **Відмітка** (Норма / Зауваження / Н/З), **Число** (поза «Мін»–«Макс» — «поза

- **«!» на початку варіанта** позначає поганий результат: вибір «!Нечітке» — зауваження
  («поза нормою»), а в критичному пункті — «Не пройдено». Варіанти в таблиці розділяються
  крапкою з комою (у формі застосунку кожен варіант пишуть з нового рядка).
- «Критичний» = так: зауваження в цьому пункті робить чек-лист «Не пройдено».
- Необов'язкові стовпці: «Підказка» (текст для оператора), «Порядок» (сортування).

### Як додати роботу регламенту прямо в таблиці

Новий рядок на аркуші «Регламент ТО і ППР». Обов'язкові: **ID**, **ID лінії**, **Робота**
і хоча б один інтервал:

- «Інтервал, днів» — календар;
- «Інтервал, мотогодин» — за мотогодинами **лінії**;
- «ID лічильника» + «Інтервал за лічильником».

Необов'язкові стовпці:

- «ID агрегату», «Вид» (ТО, ППР, Заміна деталі, Змащування…), «Деталь / вузол»,
  «Інструкція» (її бачить оператор і вона потрапляє в лист);
- «Попереджати за, днів» / «Попереджати з, %» — власні пороги «Скоро»
  (якщо порожньо, діють загальні 7 днів / 90 %);
- «Email для сповіщень» — додаткові адреси для цієї роботи;
- «Відлік від дати» — коли роботу востаннє виконали до початку обліку. Якщо стовпець
  порожній, відлік іде від моменту, коли система вперше побачить рядок (перше ж оновлення
  планшета чи кабінету записує цей момент у стовпець);
  «Відлік мотогодин лінії» / «Відлік лічильника» за порожнього значення рахуються за
  журналом на цю дату.
- Для інтервалу **за мотогодинами** дата сама по собі не враховує години, відпрацьовані до
  початку обліку: відлік почнеться з нуля. Щоб урахувати їх, у «Відлік мотогодин лінії»
  впишіть поточні мотогодини лінії мінус напрацювання з останнього виконання. До початку
  обліку це від'ємне число: `-480` означає «з останньої заміни вже відпрацьовано 480 год».
  Так само для «Відлік лічильника». Простіше додати таку роботу в застосунку
  (Керівництво → Обладнання → «Регламент ТО і ППР»): там є поля «Востаннє виконано» і
  «Напрацювання відтоді».

### PIN

- **PIN працівника** — 4–8 цифр, необов'язковий. Стовпець «PIN» має формат «Звичайний
  текст», тому `0427` зберігається з нулем; не змінюйте формат цього стовпця. На планшети
  передається лише хеш PIN. Некоректний PIN (наприклад, `427`, коли нуль загубився) буде
  позначено на «Огляді» керівника.
- **PIN керівника** зберігається не в таблиці, а у властивостях скрипту (розділ [10](#10-обмеження-й-поради)).

## 7. Нагадування

### E-mail

Листи надсилаються з пошти власника таблиці від імені «Облік ліній».

| Лист | Коли | Кому |
|---|---|---|
| **Щоденний звіт** | щодня о `digest_hour` (типово в проміжку 7:00–8:00: Google запускає тригер у довільну хвилину цієї години). У режимі `if_any` лише тоді, коли є що повідомити. Пропущений або ненадісланий звіт (ліміт, збій пошти) надсилається пізніше того ж дня | `manager_emails` + працівники з посадою «Керівник» |
| **Настав строк ТО** | щогодинна перевірка: один лист на кожен новий строк (не щогодини повторно) | керівники, механіки, електрики + «Email для сповіщень» цієї роботи |
| **Зауваження в чек-листі** | одразу після чек-листа з результатом «Із зауваженнями» / «Не пройдено» | керівники, «Контроль якості» |
| **Ремонт / аварійна зупинка** | одразу, коли лінію переведено в стан «Ремонт» | керівники, механіки, електрики |

- `manager_emails` отримують **усі** листи.
- Працівники з «Персоналу» отримують листи за посадою, якщо вони активні й мають email.
  Якщо в людини заповнено «Лінії», вона отримує листи (крім щоденного звіту) лише про ці
  лінії. Оператори й наладчики листів не отримують.
- Щоденний звіт містить: «Потрібно виконати», «Скоро потрібно виконати», «Щоденні перевірки
  за вчора», «Без завершення зміни понад 16 год» (лінії, що зараз так довго не в «Не працює»), «Зауваження
  в чек-листах за добу», «Ремонти та простої за добу», «Стан ліній зараз». У «Щоденних
  перевірках» день позначається «Без чек-листа або завершення», якщо був запуск чи завершення
  без чек-листа або зміна (лінія працювала), що почалася того дня, тривала довше за
  `long_run_hours` без завершення (а не «Перевірки виконано»).
- Кожну миттєву розсилку можна вимкнути (`instant_due`, `instant_checklist`, `instant_repair`).
- Усі листи та помилки видно в «Керівництво → Налаштування → Журнал сповіщень» і на аркуші
  «Сповіщення» (стовпець «Статус»: «Надіслано», «Помилка»; у демо — «Демо: не надсилалося»).

### На планшеті

- **Екран лінії:** панель «ТО і ППР» з простроченими та близькими роботами. Дотик до роботи
  відкриває подробиці й кнопку «Позначити виконаним». Там само є попередження «Лінія працює
  без чек-листа запуску» і «понад 16 год без завершення».
- **Плитки ліній:** значки «ТО: N прострочені», «ТО скоро: N», «без чек-листа»,
  «понад 16 год без завершення», «очікує синхронізації». Угорі головного екрана є лічильники
  «ТО прострочено» / «ТО скоро».

### Ліміти пошти Google

Google обмежує кількість **одержувачів** листів зі скрипту на добу. Орієнтовно це близько
**100** для звичайного облікового запису Gmail і **1500** для Google Workspace. Точні й
актуальні значення дивіться на сторінці
[Quotas for Google Services](https://developers.google.com/apps-script/guides/services/quotas).
Рахуються саме одержувачі: лист на 3 адреси витрачає 3 одиниці ліміту.

Коли ліміт вичерпано, лист не надсилається, а в «Журналі сповіщень» з'являється помилка
«Вичерпано денний ліміт листів Google». Лист про строк ТО система спробує надіслати знову
наступної години; щоденний звіт — теж щогодини до кінця того ж дня (без отримувачів повтору
немає). Миттєві листи про чек-лист чи ремонт повторно не надсилаються, але ці зауваження й
ремонти потрапляють у наступний щоденний звіт. Якщо ліній і адрес багато: тримайте список отримувачів
коротким, за потреби вимкніть `instant_checklist` або використовуйте обліковий запис Workspace.

## 8. План ППР

Для кожної роботи регламенту система визначає **найближчий строк** і **період повторення**:

- **за календарем** — «Інтервал, днів»;
- **за мотогодинами** — «Інтервал, мотогодин» ÷ середнє напрацювання лінії (год/добу)
  за останні `avg_window_days` (типово 28) днів;
- **за лічильником** — «Інтервал за лічильником» ÷ середній приріст лічильника за добу за той самий період.

Якщо умов кілька, береться та, що настає раніше. Від найближчого строку роботи
розставляються з цим періодом до кінця горизонту `plan_horizon_days` (типово 365 днів).
Прострочені роботи стоять у плані на сьогодні. Якщо лінія ще не працювала й прогнозу немає,
робота позначається «Немає даних про напрацювання для прогнозу».

- Аркуш **«План ППР»** (Дата, Лінія, Агрегат, Робота, Вид, Підстава, Статус) оновлюється
  **щодня** разом зі щоденним звітом і вручну — **«Облік ліній → Оновити «План ППР»»**.
  Ручні зміни на цьому аркуші буде перезаписано.
- У застосунку: **Керівництво → ТО і ППР → «План робіт»** і **«Річний графік»** (з CSV і друком).

Чим довше ведеться облік, тим точніший прогноз за мотогодинами й лічильниками.

## 9. Офлайн-робота планшета

- Кожен запис оператора спершу зберігається **на планшеті в черзі** й надсилається на сервер,
  щойно є зв'язок. Без мережі працювати можна далі: стан лінії на екрані враховує ненадіслані
  записи (позначка «Очікує синхронізації»). Після відновлення зв'язку записи надсилаються
  автоматично, у правильному порядку й без дублікатів.
- **Індикатор** у верхній панелі: «Онлайн», «Офлайн», «У черзі» / «Надсилання» з кількістю
  записів, «Невірний токен». Дотик до нього відкриває вікно **«Синхронізація»** зі списком черги
  й кнопкою «Надіслати зараз».
- Застосунок відкривається без мережі, якщо його вже хоча б раз відкривали з інтернетом
  (у «Пристрій → Про застосунок» має бути «Офлайн-режим: активний»).
- **Дії керівника** (зміни обладнання, налаштувань, анулювання) потребують зв'язку.

**Відхилені записи.** Якщо сервер остаточно відмовився прийняти запис, з'являється банер
«Сервер відхилив N записів» → **«Переглянути»**. У вікні «Синхронізація» → «Відхилено
сервером» видно причину. Найчастіші причини:

- *«Час запису … давніший за 45 дн. — перевірте дату й годинник пристрою»* — на планшеті
  збився годинник;
- запис стосується лінії, агрегату, лічильника чи роботи регламенту, рядок якої видалили
  з таблиці або змінили їй ID.

Що робити: якщо причину усунуто (наприклад, рядок повернули в таблицю), натисніть
**«Повторити»**. Інакше внесіть потрібні дані заново з правильним часом і натисніть
**«Видалити»** (або «Видалити всі відхилені»). Роботу можна внести формою «Записати роботу»
з потрібною датою (до року тому).

Якщо індикатор показує **«Невірний токен»**, записи не губляться: вони чекають на пристрої,
доки в «Пристрій → Змінити підключення» не введуть правильний токен.

## 10. Обмеження й поради

- **Швидкість.** Кожен запит до Apps Script займає приблизно 1–3 секунди. Оператор цього
  майже не помічає, бо записи йдуть через чергу. Звіти й журнал у кабінеті керівника можуть
  завантажуватися кілька секунд.
- **Місткість таблиці.** Google-таблиця вміщує до 10 млн клітинок (усі аркуші, разом із
  порожніми). Орієнтовно 3 лінії займають кількасот тисяч клітинок на рік; найбільше займає
  аркуш «Чек-листи — відповіді». Щоденний звіт попередить, коли таблиця заповниться на 70 %.
  Тоді запустіть **«Облік ліній → Архівувати старі чек-листи»**: чек-листи й відповіді,
  старші за N місяців (типово 12, щонайменше 6), буде перенесено в **нову окрему таблицю** на
  вашому Диску. Журнали стану, робіт і показників не архівуються: з них рахуються мотогодини й строки.
- **Годинник планшета.** Увімкніть автоматичну дату й час. Застосунок звіряє годинник із
  сервером («Пристрій → Годинник»), але записи з датою понад 45 днів тому (роботи — понад рік)
  сервер не приймає.
- **Резервні копії.** Google зберігає історію змін: **Файл → Історія версій → Переглянути
  історію версій**. Там можна відновити попередній стан таблиці. Для надійності періодично
  робіть **Файл → Створити копію**.
- **Токен і PIN керівника** зберігаються у властивостях скрипту: Apps Script → ⚙ «Налаштування
  проєкту» → «Властивості скрипту».
  - `ADMIN_PIN` — PIN керівника, **лише 4–8 цифр** (інший на екранній клавіатурі планшета не
    ввести; «Початкове налаштування» і «Показати токен і PIN» попередять про некоректний).
    Після зміни керівникам доведеться ввести його знову.
  - `API_TOKEN` — токен доступу. Після зміни введіть новий токен на кожному планшеті
    («Пристрій → Змінити підключення»). Доти записи чекатимуть у черзі.
  - Після 10 невдалих спроб PIN з одного пристрою (або 60 з усіх) вхід блокується до 10 хвилин.
- **Власник.** Скрипт працює від імені облікового запису, який його розгорнув. Не видаляйте
  цей обліковий запис і не забирайте в нього доступ до таблиці.
- **Кілька планшетів одночасно** — це нормально: записи на сервері виконуються по черзі, а
  якщо сервер зайнятий, планшет повторить спробу сам.

Збирати нічого не потрібно; залежностей немає (перевірено на Node.js 22).

```bash
cd lines
npm test            # ядро і сервер (node --test)
npm run test:e2e    # наскрізні тести в Chromium (потрібен Playwright; без нього тест пропускається)
npm run test:all    # усе разом
npm run dev         # емулятор: http://localhost:8787/ · адреса …/exec · токен dev-token · PIN 1234
```

Службові адреси емулятора (`/__control`, `/__sheets`, `/__mails`, `/__requests`) і параметри
